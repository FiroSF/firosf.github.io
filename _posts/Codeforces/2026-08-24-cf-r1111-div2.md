### [A번 - Zero Sum](https://codeforces.com/contest/2247/problem/A)


* $1$의 수를 $p$, $-1$의 수를 $q$라 하자.
* 연산을 어떻게 해도 $\vert p - q \vert \bmod 4$ 값은 변하지 않는다.
  * $-1$ 두개가 $1$ 두개로 바뀌거나, 반대거나, 개수가 변하지 않거나
* 따라서 $p \equiv q \pmod{4}$여야 한다.
* **분류**: 정수론, 애드 혹

* $\bmod 4$인걸 알아차리기가 생각보다 어려웠다.

### [D1번 - XOR Sorting (Easy Version)](https://codeforces.com/contest/2247/problem/D1)

* 먼저 $k = 1$일 때를 생각해 보자.
  * $0$과 $1$, $2$와 $3$, $4$와 $5, \dots$처럼 이진수의 첫째 자리(최하위 비트)만 차이 나는 수들끼리 swap(교환)이 가능하다.
* $k = 2$일 때는 $0$과 $2$, $1$과 $3$, $4$와 $6$, $5$와 $7$처럼 이진수의 둘째 자리 비트만 다른 수들끼리 swap이 가능하다.
* 그런데 $k = 2$일 때는 $k = 1$일 때의 swap 연산을 포함한다.
* 따라서 ${0, 1, 2, 3}$끼리 자유롭게 swap이 가능하고, ${4, 5, 6, 7}$끼리도 자유롭게 swap이 가능하다.
  * 즉, 크기 $2^2$ 단위의 블록으로 분리된다.
* 같은 원리로 $k = 4$일 때를 생각해보면, 크기 $4$짜리 블록 $2$개를 서로 이어주는 역할을 한다.
* 결과적으로 $[0, 7]$, $[8, 15], \dots$와 같이 크기 $2^3$ 단위의 블록으로 묶인다.
* 따라서 다음과 같이 풀면 된다.
  * 블록 크기를 $1, 2, 4, 8, \dots, 2^{19}$까지 $2$의 거듭제곱 형태로 늘려간다.
    * 각 블록 내에서 정렬한 결과가 전체를 정렬한 결과와 일치하는지 확인한다.
* 세그트리처럼 배열을 나눠 생각해주면 되는 문제였다.
* **분류**: 비트마스킹, 그리디

### [D2번 - XOR Sorting (Hard Version)](https://codeforces.com/contest/2247/problem/D2)

* Easy 버전에서 다음과 같은 결론을 얻을 수 있다:
  * $k$가 무조건 $2^n$ 꼴이어야 한다.
  * $k = 2^n$이라 할 때, 커버할 수 있는 블록 크기는 $2k$이다.
* 나올 수 있는 블록의 총 개수는 $N \log N$개다.
  * 크기 $1$개짜리 $N$개, $2$개짜리 $N/2$개, $4$개짜리 $N/4$개, $\dots$ 다 더하면 $O(N \log N)$
* Easy에서 한 것처럼 블록별로 정렬을 해 보자.
  * 다만, 여기서는 분할정복으로 머지소트하듯이 정렬하자.
* 구간 $[l, r]$에 대해서 중심 $m = (l + r) / 2$을 잡자.
* 그럼 분할정복을 $[l, m]$이랑 $[m+1, r]$ 각각에 대해 해 준다.
* 이제 얘네들을 합쳐야 한다.
* 이때 왼쪽 덩어리의 최대가 오른쪽 덩어리의 최소보다 커버리면 둘 사이에 swap이 일어나야 한다.
  * 이 경우 $k$는 적어도 구간 길이의 절반이다. (Easy의 결론)
* 그러면 모든 블록들에 대해서, '$k$가 $m - l + 1$이어야만 해당 블록을 정렬할 수 있는가?'를 풀면 된다.
* 이걸 이제 세그 노드에다가 박아준다.
* 그러려면 세그 노드에다가 $\min$, $\max$, $k$값을 들고 다니면서...
  * 합칠 때마다 $k$를 갱신해야 하는지 말아야 하는지를,
  * 왼 덩어리 $\max$랑 오른 덩어리 $\min$을 비교해서 알아내면 된다.
* 이게 업데이트하는 쿼리 하나당 블록 $\log N$개가 건드려져서 $O(Q \log N)$으로 풀린다.
* **분류**: 비트마스킹, 그리디, 분할 정복, 세그먼트 트리

#### 고찰

* 실제 대회때는 아예 저 접근 자체를 못 했다.
  * Easy에서 한 것처럼 머지소트 느낌으로 가야 했다.
  * 그런데 나는 부분정렬을 한다는 생각을 못 했다.
    * 실제로 Easy 풀 때도 분할정복이라는 생각을 안 했었다.
* 가장 큰 문제는... 전체 정렬에만 매몰되어 있던 점인 것 같다.
* 그래서 모든 원소들의 rank를 관리해야 한다고 생각했다.
* 흠... 그러면 얘네를 세그에 얹어야 할 것 같은데...
  * 관리해야 할 게 인덱스랑 rank 두개나되네??
  * 근데 원소 추가하면 rank를 구간 업데이트해야하잖아
  * 근데 인덱스는 안변하네?
  * 그럼 rank순으로 세그를 만들자!
* 이런 느낌으로 접근해버렸다...
* 그러면 이제 인덱스가 다 조각나버린다.
  * 이걸 관리하려면 수별로 몇까지 더해야 xor의 msb가 바뀌는지 알아내야 하고...
  * 그러면 최대 비트개수인 $20$가지 언저리를 관리해야 하고...
  * 이러면 무조건 로그제곱이 붙는다.

// 2026-08-24 19:10:55
#include <bits/stdc++.h>

using namespace std;

#define all(a) a.begin(), a.end()
#define F first
#define S second
#define INF 0x3f3f3f3f
#define MOD 998244353
#define ll long long
#define pii pair<ll, ll>
#define piii pair<ll, pii>

struct Calc {
    static constexpr piii def = {0, {INF, 0}};
    piii operator()(piii a, piii b, ll k) const {
        piii res = {max(a.F, b.F), {min(a.S.F, b.S.F), max(a.S.S, b.S.S)}};
        if (a.S.S > b.S.F)
            res.F = k;
        return res;
    }
};

template <typename Op> class Segtree {
  public:
    int siz;
    vector<piii> arr;
    Op op;

    Segtree(int n) {
        siz = 1 << (32 - __builtin_clz(n));
        arr.assign(siz * 2, Op::def);
    }

    void update(int idx, ll val) {
        idx += siz;
        arr[idx] = {0, {val, val}};
        int cnt = 1;
        while (idx /= 2) {
            arr[idx] = op(arr[idx * 2], arr[idx * 2 + 1], cnt);
            cnt *= 2;
        }
    }

    // [l, r]
    piii query(int l, int r) {
        piii resl = Op::def;
        piii resr = Op::def;
        int k = 1;
        for (l += siz, r += siz; l <= r; l /= 2, r /= 2) {
            if (l % 2 == 1)
                resl = op(resl, arr[l++], k);
            if (r % 2 == 0)
                resr = op(arr[r--], resr, k);
            k *= 2;
        }
        return op(resl, resr, k);
    }
};

### [E번 - Build a Tree](https://codeforces.com/contest/2247/problem/E)


* 일단 홀수가 절대 나올 수 없다.
  * 시작을 $s$, 방문하는 지점 중 아무거나 하나를 $t$라 하자.
  * $s$에서 $t$를 갈 때랑 $t$에서 $s$로 올 때 거치는 간선의 홀짝은 항상 일치해야 한다.
  * 이게 단순 경로가 아니라서 애매하다 생각할 수 있다.
  * 근데 저 분할하는걸 계속 하다보면 언젠간 단순 경로가 된다.
  * 트리에서의 단순 경로는 최단 경로뿐이므로 저런 일이 일어날 수 없다.
  * 증명 일케하는거 맞나근데?
  * gemini한테 물어보니까 그냥 이분그래프라 시작과 끝 색이 같으면 지나간 edge 개수가 짝수개라고 한다.
    * 생각해보니까 당연하네...
* 최소는 $2(N-1)$이다.
  * $1 - 2 - 3 - 4 - \cdots$형태로 이어진 트리이다.
  * 어찌 되었든 왕복해야 하므로 이게 최소가 된다.
* 최대는 $\displaystyle \frac{N(N - 1)}{2} + \left\lfloor \frac{N}{2} \right\rfloor$ 이다.
  * 증명 솔직히 어떻게 하는지 잘 모르겠다.
  * 다음과 같은 트리를 생각하자.
    * $\cdots - 6 - 4 - 2 - 1 - 3 - 5 - 7 - \cdots$
  * $1$번 정점부터 차례로 배치한다고 생각하자.
  * 그러면 $k$번 정점을 배치할 때, 배치된 모든 간선을 한 번씩 지난다.
  * 다만, 회로를 만들어야 하므로 마지막에 $1$로 가야 한다.
    * 이 때는 모든 간선을 지나지는 않는다.
  * 흠근데 이거보다 많이 지나갈수있나?? 생각해봤을 때 절대 안될거같아서 이게 최선이라고 생각하고 넘어갔다.
  * gemini피셜 증명 이렇게 하면 된다고 한다(귀찮아서 제대로 안읽음).
    * 트리에서 어떤 간선 $e$를 자르면 트리가 두 개의 컴포넌트(크기 $A$와 $B$)로 나뉩니다.
    * $1 \to 2 \dots \to N \to 1$로 이동하는 동안 간선 $e$를 건널 수 있는 최대 횟수는 $2 \times \min(A, B)$번입니다. (한쪽으로 넘어갔으면 반드시 다른 쪽으로 돌아와야 하므로)
    * 트리의 중심(센트로이드)을 기준으로 트리를 양분했다고 생각해보세요. 전체 거리의 합을 최대화하려면, **1, 2, 3, 4... 순서대로 방문할 때마다 센트로이드를 가로질러 반대편 서브트리로 점프**해야 합니다.
    * 작성자님이 고안하신 $\cdots - 6 - 4 - 2 - 1 - 3 - 5 - 7 - \cdots$ 트리는 이 조건을 완벽하게 만족합니다. 번호가 1씩 커질 때마다 트리의 중심(1과 2 사이)을 가로지르며 좌우를 왕복하기 때문에, 이론적으로 가능한 모든 간선 통과 횟수의 최댓값을 정확히 달성합니다. 따라서 직관적으로 도출하신 식이 수학적인 최대 상한선이 맞습니다.
* 최대랑 최소 모두 일자모양 트리이다.
* 이 일자모양 트리에서 정점을 어느 타이밍에 적절한 곳에 붙여 원하는 수를 만들 수 있을 거라는 생각을 했다.
* $6 - 4 - 2 - 1 - 3 - 5 - 7$을 생각하자.
  * 지금 $k$값은 $24$다.
* 여기에 $8$을 적절하게 붙이자.
* $1, 3, 5, 7$에 붙이면 $k$가 $2$ 늘어난다.
  * 이는 최소인 $2(N-1)$에서 달성되는 값이다.
* $2, 4, 6$에 붙이면 $k$가 $4, 6, 8$씩 늘어난다.
* 즉, 우리는 증가량을 $2, 4, 6, 8$에서 마음대로 정할 수 있다.
* 이때 기본적으로 노드 하나를 붙일 때 $2$씩은 반드시 증가한다.
* 따라서 초기값을 $2(N-1)$로 놓는다면, 증가량을 $0, 2, 4, 6$으로 생각할 수 있다.
* 그러면 이제 최대인 일자트리를 만들면서 증가량 딱 맞추고 나머지는 $1$번 노드같은 곳에 이어 붙이기만 하면 된다.
* 에디토리얼은 센트로이드 기반 풀이를 설명하고 있는데... 뭔지 잘 모르겠다.
* **분류**: 트리, 해 구성하기, 증명이 어려운
